# AllTheScripts content patterns

Use these patterns to add verified material without redesigning the website. Omit optional sections completely when content is unavailable; never leave an empty heading, gallery, card or launch control.

## Project page

Minimum supplied content:

- name, type and honest status
- one-sentence result or current objective
- concise purpose
- Darren's role
- tools that were actually used
- at least one real item of evidence, or an explicit in-development state
- known limitations

Optional sections: playable build, major systems, selected process, image/video gallery, source or store links, and AI-assistance disclosure where relevant.

Recommended order: result → status and purpose → evidence → Darren's contribution → systems → limitations → optional process.

## Playable prototype or tech demo

Minimum supplied content:

- exact feature or technical question demonstrated
- maturity label
- what the demonstration proves
- platform and input requirements
- known limitations
- real screenshot/poster, video or working build

Optional sections: controls, performance expectations, implementation notes and source link. A heavy build must use the shared intentional launch pattern and must never load with the page.

## System showcase

Minimum supplied content:

- problem the system addresses
- visible result
- Darren's decisions and contribution
- tools and technical context
- working evidence such as a capture, diagram or small demonstration
- limitations or deliberately excluded scope

Optional sections: before/after comparison, architecture detail, reusable lessons and source excerpts.

## Workflow entry

Minimum supplied content:

- outcome the workflow enables
- when to use it
- concise ordered method
- validation or completion check
- limitations

Optional sections: diagram, downloadable Markdown source, short copyable block, worked example, GitHub source and meaningful reviewed date. Prompts remain secondary to the decisions and output they enable.

## Shared field behaviour

All patterns support result, purpose, evidence, role, tools, limitations and optional process. Status uses the approved labels from the rebuild brief. Media needs meaningful alternative text or a caption; decorative colour treatments must not be described as project evidence. External links identify their destination, and build launch controls appear only for validated builds.
