Workflow

A field manual for turning ideas into workable slices.

This is the reusable structure I maintain for planning, implementing and validating game-development work with Codex. It is a working reference, not a blog or a prompt collection.

Core process

From idea to verified change

The output at each stage becomes the grounded input for the next.

  1. Shape the idea

    Turn the initial concept into a descriptive overview with a clear player experience, boundaries and unknowns.

  2. Find modules and slices

    Break the overview into systems, dependencies and small pieces that can be completed and tested.

  3. Write the task list

    Give Codex ordered work, acceptance criteria, preservation rules and explicit stopping points.

  4. Implement in Unity

    Build one meaningful slice while keeping project, module and scene structure deliberate.

  5. Validate the result

    Test behaviour, inspect the visible output and compare it with the agreed acceptance criteria.

  6. Maintain documentation

    Record decisions, current limitations and the next useful boundary while the context is fresh.

  7. Commit the slice

    Create a clear Git commit when a major slice is complete and verified.

Quick utility

A short slice boundary

The essential structure stays visible; extra explanation remains optional.

Result → Included → Excluded → Dependencies → Acceptance checks → Stop

Why define the stop condition?

A clear completion boundary prevents one useful slice from quietly absorbing adjacent work. Remaining ideas become later tasks instead of unverified additions.
