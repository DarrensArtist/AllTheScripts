Authority model

Discussion, truth, role and reality are distinct.

Chats preserve useful working context. Documents and repository state determine what is currently authoritative.

Context space

Chat

Persistent reasoning and discussion. Useful, but non-authoritative.

Approved truth

Document

Preserves approved intent for its specified responsibility.

Active role

Agent

Defines who is reasoning now and the boundary they must respect.

Current reality

Repository

Authoritative for the software and assets that currently exist.

Continuous Development

Brainstorm → Creator Approval → Update Owning Truth → Capability Impact Check → Re-enter at Owning Level → Propagate Downward → Implement → Validate → return to Idea Workspace when creativity continues

Re-entry rule: travel upward only as far as necessary, then propagate approved change through every affected downstream level.
