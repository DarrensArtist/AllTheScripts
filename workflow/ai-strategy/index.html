Workflow 1.0 · AI Strategy

Give every agent a role, an authority boundary and a place to return to.

AI collaboration becomes reliable when specialist responsibility, persistent workspace, approved context and stop conditions are explicit. The creator retains approval and accountability throughout.

Agent directory

Expand a role to see its contract. Persistent chat is used only where long-running specialist context adds value.

Idea WorkspaceNormal ChatGPTOpen-ended idea exploration

Inputs: questions, observations, experiments and creative possibilities. Outputs: candidate ideas and an approved Idea Brief.

Boundary: discussion is non-authoritative until creator approval. Stop: do not represent exploration as approved truth.

Persistent · WorkDesign AgentArchitecture-ready game design · High reasoning

Inputs: approved Idea Brief. Output: Game Design Brief.

Boundary: game design, not technical architecture. Stop: creator decision or material experience detail is missing.

On demandBible Maintenance AgentMaintain approved design truth

Inputs: approved design changes. Output: current Game Design Bible.

Boundary: preserve and organise approved truth; do not invent or approve it. Stop: source decisions conflict.

Persistent · WorkArchitecture AgentCapabilities, authority and dependency direction · Extra High

Inputs: Game Design Brief and relevant Bible truth. Outputs: Architecture and Module Map.

Boundary: owns capability and module decisions. Stop: game-level design is unresolved or creator approval is required.

Module Work chatModule AgentComplete module requirements

Inputs: Architecture, Module Map entry and Bible truth. Output: Module Requirements.

Boundary: one module’s responsibilities and contracts. Stop: ownership is unclear or another module must change.

Same Module chatSlice AgentComplete Slice Map and specifications

Input: approved Module Requirements. Outputs: complete Slice Map and Slice specifications.

Boundary: defines required results, not a technical task list. Stop: module requirements are unresolved.

Persistent · CodexCodexRepository-aware implementation · one chat per module

Inputs: repository reality, AGENTS.md, Architecture, Module Requirements and current Slice. Outputs: implementation, tests and evidence.

Boundary: inspect before planning; implement only the approved Slice. Stop: work crosses ownership, collides or lacks authoritative detail.

IndependentValidation AgentCompare evidence with specification

Inputs: authoritative specification and implementation evidence. Output: Pass, Pass With Deviations, Fail or Blocked.

Boundary: challenge implementation context; do not approve missing product decisions. Stop: evidence cannot support a result.

Read onlyProject LibrarianRetrieve minimum authoritative context

Inputs: precise context request and document relationships. Output: minimum current sources, deprecated distinctions and reported conflicts.

Boundary: may not resolve conflicts, approve decisions, modify truth or replace an owning specialist. Stop: ownership or current authority cannot be established.

Project Librarian

May

  • Follow recorded relationships.
  • Return minimum relevant context.
  • Distinguish current from deprecated material.
  • Report conflicts.

  • Resolve conflicts or approve decisions.
  • Modify project truth.
  • Become an authoritative source.
  • Replace the owning specialist agent.

Module, Slice and implementation reasoning rises with complexity, dependency and downstream consequence—not with ceremony.

Authoritative context strategy

  1. Retrieve the minimum complete authoritative context.
  2. Prefer approved source documents over reconstructed summaries.
  3. State the current workflow stage and exact objective.
  4. Keep unresolved material visibly unresolved.
  5. Never let conversation history overrule newer documentation.
  6. Inspect repository reality before implementation planning.
  7. Separate self-validation from independent validation.
Universal stop conditions

Pause when continuing would invent or collide.

  • A material decision is missing or authoritative documents conflict.
  • Work exceeds the active role or ownership is unclear.
  • Implementation crosses another module’s ownership.
  • Concurrent work would touch shared targets.
  • Validation cannot support the claimed result.
